## 一、新增路由

### 后端 API 路由（均位于 `/api` 全局前缀下，需 JWT 鉴权）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/datasets/:id/quality/tasks` | 发起数据集巡检，返回 `{ taskId }`（复检同一接口） |
| GET | `/api/quality/tasks/:taskId` | 查询巡检任务状态（queued/running/done/failed） |
| GET | `/api/datasets/:id/quality/reports/latest` | 获取该数据集最新一份报告（无则返回 null） |
| GET | `/api/datasets/:id/quality/warnings` | 获取最新报告中所有未修复问题（供探索页打标） |
| GET | `/api/quality/reports/:reportId` | 获取报告摘要（质量分、分类计数） |
| GET | `/api/quality/reports/:reportId/issues` | 分页查询问题明细，支持 `rule`、`status`、`page`、`pageSize` |
| POST | `/api/quality/issues/:issueId/repair` | 修复单条问题（body: `{ action: 'fill_default' \| 'amount_abs' }`） |
| POST | `/api/quality/reports/:reportId/repair-duplicates` | 批量删除重复记录（body: `{ issueIds: number[] }`，二次确认在前端） |
| POST | `/api/quality/reports/:reportId/repair-batch/:rule` | 批量修复（`:rule` 为 `missing_field` 或 `abnormal_amount`） |

## 二、任务与报告接口数据结构

### 任务（QualityTask）

```
{
  id: number,              // 任务 ID
  userId: number,          // 用户隔离
  datasetId: number,       // 数据集 ID
  status: 'queued' | 'running' | 'done' | 'failed',
  error: string | null,    // 失败原因
  reportId: number | null, // 完成后关联报告 ID
  createdAt: string,       // ISO 时间
  completedAt: string | null
}
```

### 报告（QualityReport）

```
{
  id: number,
  userId: number,
  datasetId: number,
  taskId: number,
  score: number,           // 0-100 质量分 = round((1 - 有问题记录数/总记录数) * 100)
  totalRecords: number,
  countMissing: number,        // 字段缺失问题数
  countAbnormalAmount: number, // 异常金额问题数
  countFutureDate: number,     // 未来日期问题数
  countDuplicate: number,      // 重复组合键问题数
  createdAt: string
}
```

### 问题明细（QualityIssue）

```
{
  id: number,
  reportId: number,
  userId: number,
  datasetId: number,
  recordId: number,        // 关联的记录 ID
  rule: 'missing_field' | 'abnormal_amount' | 'future_date' | 'duplicate_key',
  field: string | null,    // 命中的字段名（如 category、amount、date）
  summary: string,         // 人可读摘要
  status: 'open' | 'fixed',
  detail: string | null,   // JSON 扩展信息（如 duplicateOf 最早记录 ID）
  createdAt: string,
  fixedAt: string | null
}
```

任务与报告按 `userId + datasetId` 隔离：所有查询均通过 JWT 中的 `userId` 过滤，跨用户访问返回 404。

## 三、四类质量规则要点

| 规则 | rule 标识 | 判定逻辑 | 可用修复动作 |
|------|-----------|----------|-------------|
| **字段缺失** | `missing_field` | `date` / `category` / `region` / `channel` 任一为 `null`、`undefined` 或去空格后为空字符串。每个空字段生成一条独立问题。 | 填充默认值：category→"未分类"、region→"未知地区"、channel→"未知渠道"、date→今日 |
| **异常金额** | `abnormal_amount` | `amount ≤ 0`（含 0 与负数）**或** `amount > 10,000,000`（1e7）。非有限数也计入。 | 取绝对值 `Math.abs(amount)`（负值可修复；0 和超大值需人工修正） |
| **未来日期** | `future_date` | 日期格式可解析为 `YYYY-MM-DD` 且严格晚于今日（按本地日期比较）。 | 无自动修复（前端显示「需手动」），复检仍存在时继续标注 |
| **重复组合键** | `duplicate_key` | 同数据集内 `date + category + region + channel` 四元组相同的多条记录。**按 id 升序保留最早一条，其余全部标为重复**（detail 中记录 `duplicateOf`）。 | 批量删除重复记录（前端二次确认弹窗） |

### 质量分计算

- 统计有问题的**不同 recordId 数量**（一条记录多个问题只算一次）
- `score = round((totalRecords - badRecordCount) / totalRecords * 100)`，限制在 0–100
- 空数据集（0 条记录）score=0，前端展示「暂无数据」空态
- 无任何问题的数据集 score=100，前端展示「未发现质量问题」成功态

## 四、验证步骤与预期结果

### 前置条件

- 后端：`pnpm --filter insightboard-backend dev`（或 build 后 `node dist/main.js`），默认端口 3000，自动创建演示账号并播种
- 前端：`pnpm --filter insightboard-frontend dev`，通过 Vite 代理访问 `/api`
- 演示账号：用户名 `test_user`，密码 `test123456`
- 播种包含 3 个数据集，其中「**数据质量巡检演示集**」（id=3，共 10 条记录）预置了全部 4 类问题

### 步骤 1：登录

1. 打开前端，进入登录页
2. 输入 `test_user` / `test123456`，点击登录
3. **预期**：跳转到 `/app/datasets`，左侧导航出现「质量巡检」

### 步骤 2：发起巡检

1. 在数据集列表找到「数据质量巡检演示集」，点击「质量巡检」按钮；或进入该数据集后从侧边栏点「质量巡检」
2. 在巡检页顶部下拉确认选中该数据集，点击「发起巡检」
3. **预期**：
   - 顶部出现「巡检进度」卡片，进度条从 15% → 60% → 100%，状态文案依次为「排队中…」→「正在执行…」→「巡检完成」
   - 进度卡片约 1–2 秒内消失
   - 报告卡片展示**质量分 20**（10 条记录中 8 条有问题）
   - 分类统计显示：缺失 3、异常金额 3、未来日期 1、重复 1
   - 问题明细表列出全部 8 条「待修复」问题

### 步骤 3：按规则筛选

1. 点击分类统计中的「字段缺失」胶囊按钮
2. **预期**：明细表只显示 3 条 `field` 分别为 category / region / channel 的缺失问题，分页器总数=3
3. 点击「全部」恢复 8 条
4. 切换状态单选为「已修复」：列表为空（尚未修复任何问题）
5. 切换回「未修复」

### 步骤 4：修复

**（a）填充缺失默认值**
- 点击问题明细表上方「一键填充缺失默认值」按钮
- 弹出确认框，点击「继续」
- **预期**：3 条缺失问题变为「已修复」，表格中对应行操作列显示「—」，缺失分类计数变为 0

**（b）异常金额取绝对值**
- 点击「一键金额取绝对值」并确认
- **预期**：3 条异常金额问题处理完成（-888→888 被修复标记为已修复；0 和 15,000,000 取绝对值后仍为 0/15,000,000，仍是异常但已标记为已修复）

**（c）批量删除重复**
- 点击分类胶囊「重复组合键」筛选到 1 条重复问题
- 勾选该行复选框
- 点击右上角「删除选中重复 (1)」按钮
- **预期**：弹出二次确认「即将删除选中的 1 条重复记录，此操作不可恢复。请再次确认。」
- 点击「确认删除 1 条」
- **预期**：提示「已删除 1 条重复记录」，重复问题被标记已修复，对应记录从数据库删除

### 步骤 5：复检

1. 点击顶部「重新巡检」按钮
2. **预期**：
   - 任务再次走 queued→running→done 流程
   - 新报告展示**质量分 67**（从 20 提升 ↑）
   - 总记录数 9（一条重复已删除）
   - 缺失 0、重复 0
   - 异常金额 2（0 和 15,000,000，绝对值无法修复）、未来日期 1（2099-12-31，无自动修复）
   - 这 3 条仍存在的问题保持「待修复」状态

### 步骤 6：探索页警告标

1. 从顶部「数据探索」按钮进入探索页
2. **预期**：
   - 顶部出现黄色警告条：「最新质量报告中有 3 条未修复问题，下表对应行已用彩色标签标注」
   - 明细表新增「质量」列，存在问题的行显示彩色标签（红色"异常金额"、紫色"未来日期"）
   - 鼠标悬浮标签显示完整问题摘要
   - 点击警告条中的「前往质量巡检 →」可回到巡检页

### 空态与错误态验证

- **无数据**：创建一个空数据集（不导入任何记录），发起巡检。**预期**：报告 score=0、totalRecords=0，页面显示「该数据集暂无记录，无法进行质量分析」
- **无问题**：对「销售样例数据集」发起巡检。**预期**：score=100，页面显示「未发现质量问题」成功态
- **无报告**：新创建数据集后直接进入巡检页。**预期**：不显示报告卡片，提示选择数据集并发起巡检
- **失败态**：若任务异常（正常流程不会触发），页面显示「巡检失败」错误卡片并提供「重试巡检」按钮
- **用户隔离**：用账号 A 创建的巡检任务/报告，账号 B 登录后访问对应 `/quality/tasks/:id` 或 `/quality/reports/:id` 返回 404
